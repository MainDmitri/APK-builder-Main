# AppBuilder — APK из ZIP-архива прямо с телефона

**AppBuilder** превращает ZIP-архив с кодом в готовое подписанное Android-приложение (APK).
Компьютер и Android Studio не нужны: сборка идёт бесплатно в GitHub Actions, а APK можно сразу
установить на телефон.

Что можно собрать:

- **сайт или веб-приложение** на HTML / CSS / JavaScript;
- **проект на React, Vue, Svelte, Vite, Phaser, Three.js** (npm, yarn или pnpm): сначала выполняется
  `npm run build`, затем результат упаковывается в APK;
- **нативное Android-приложение** на Kotlin или Java (Jetpack Compose или обычные View), в том числе
  только исходники без Gradle-файлов.

Главная идея: попросить ChatGPT / Claude / DeepSeek написать приложение, упаковать ответ в ZIP —
и получить APK. Встроенный генератор промптов объясняет нейросети все правила сборщика, поэтому код
собирается с первого раза.

## Возможности

- **Автоопределение проекта**: `package.json` → `index.html` → Android-исходники. Проект находится
  и во вложенных папках (`client/`, `frontend/`, `web/`, `android/`…), лишнее (`server/`, `docs/`)
  в APK не попадает.
- **Генератор промптов** (вкладка «Промпты»): тип приложения, название, пакет, ориентация, разрешения,
  хранилище данных, цвет, язык → кнопка «Скопировать мега-промпт».
- **Контракт для ИИ** (вкладка «Контракт»): полные правила сборщика, кнопка «Экспорт контракта для ИИ».
- **Веб-приложения работают как настоящие**: localStorage и IndexedDB сохраняются, работают выбор
  файлов, камера, микрофон, геолокация, вибрация, скачивание файлов, полноэкранный режим,
  системная кнопка «Назад».
- **Подпись**: постоянный Debug Key (новые версии ставятся поверх старых), свой keystore
  с проверкой паролей или keystore из секретов GitHub. zipalign + подпись v1 + v2 + v3.
- **История сборок**: все APK остаются в Releases вашего репозитория, их можно скачать повторно.
- Приложение работает на Android, Windows, Linux и в браузере.

## Как пользоваться

### 1. Установите приложение

Откройте **Releases → app-latest** и скачайте на телефон `AppBuilder-*.apk`.
При установке Android попросит разрешить установку из этого источника — разрешите.

### 2. Создайте свой сборщик (один раз)

1. Зарегистрируйтесь на [github.com](https://github.com), если ещё нет аккаунта.
2. На странице этого репозитория нажмите **Use this template → Create a new repository**.
3. Придумайте имя (например, `my-apk-builder`) и выберите видимость:
   - **Private** — ваши проекты и APK никто не увидит (бесплатно 2000 минут сборки в месяц,
     одна сборка занимает 3–6 минут);
   - **Public** — минуты без ограничений, но архивы и APK видны всем.
4. Нажмите **Create repository**.

Сборки пойдут в **вашем** репозитории: чужие пользователи ваших приложений не видят, а вы — их.

### 3. Создайте токен доступа

1. Откройте https://github.com/settings/personal-access-tokens/new
2. **Token name** — любое, например `AppBuilder`; **Expiration** — срок действия (можно до года).
3. **Repository access → Only select repositories** → выберите репозиторий из шага 2.
4. **Permissions → Repository permissions**:
   - **Contents** → **Read and write**;
   - **Actions** → **Read-only**.
5. Нажмите **Generate token** и скопируйте токен `github_pat_…` — он показывается только один раз.

### 4. Подключите приложение

Вкладка **«Настройки»** → **GitHub Actions** → введите:

- **владелец** — ваш логин на GitHub;
- **репозиторий** — имя репозитория из шага 2;
- **токен** — из шага 3;
- ветку можно не указывать.

Нажмите **«Сохранить и проверить подключение»**.

### 5. Получите код приложения

Если кода ещё нет — вкладка **«Промпты»**:

1. Выберите тип: утилита, веб-сервис, игра, нативное Android или React/Vue-приложение.
2. Введите название и опишите, что должно делать приложение (экраны, кнопки, данные —
   чем подробнее, тем лучше).
3. Выберите ориентацию, разрешения, способ хранения данных, цвет и нейросеть.
4. Нажмите **«Скопировать мега-промпт»** и вставьте его в ChatGPT / Claude / DeepSeek.
5. Сохраните файлы из ответа нейросети и упакуйте их в ZIP (на телефоне — через файловый менеджер,
   например «Файлы» или ZArchiver).

**Важно:** файлы должны лежать в корне архива, а не внутри папки:

```
✅ правильно               ❌ нежелательно
index.html                 my-app/index.html
app.js                     my-app/app.js
appbuilder.json            my-app/appbuilder.json
```

### 6. Соберите APK

1. Вкладка **«Сборка»** → **«Выбрать ZIP»**. Приложение сразу покажет, что за проект найден,
   и подставит название, пакет и версию.
2. Проверьте название, имя пакета (`com.example.myapp`), версию, ориентацию и разрешения.
3. Подпись: оставьте **Debug Key**, если приложение для себя.
4. Нажмите **«Собрать APK»** и подождите 3–6 минут — на экране видны этапы и журнал сборки.
5. Нажмите **«Установить»** или **«Сохранить APK»**.

Все прошлые сборки — во вкладке **«История»** и в Releases вашего репозитория (`build-…`).

### Обновление приложения

Соберите новую версию с **тем же именем пакета**, **большим versionCode** и **той же подписью** —
APK установится поверх старого, данные сохранятся.

## Частые проблемы

| Проблема | Что делать |
|---|---|
| «Приложение не установлено» | На телефоне уже стоит приложение с тем же пакетом, но другой подписью — удалите старое или смените имя пакета. Также проверьте, что versionCode не меньше установленного. |
| Play Protect предупреждает | Нажмите «Подробнее → Всё равно установить»: приложение подписано вашим ключом, а не ключом Google Play. |
| «index.html не найден» | Проверьте, что в ZIP есть `index.html`, `package.json` или исходники Android, а не другой архив внутри архива. |
| Ошибка подключения в настройках | Проверьте логин, имя репозитория и права токена (Contents: Read and write, Actions: Read-only). Если срок токена истёк — создайте новый. |
| Сборка упала | Откройте журнал в приложении: там указана причина (ошибка в коде, неверный пакет и т.п.). Отправьте её нейросети вместе с кодом и попросите исправить. |

## Своя подпись (для Google Play и надёжных обновлений)

- **Разово:** в разделе подписи выберите **Production Keystore**, укажите файл `.jks` / `.keystore` /
  `.p12`, пароль, alias и нажмите «Проверить пароли и alias».
- **Постоянно:** в вашем репозитории Settings → Secrets and variables → Actions добавьте
  `KEYSTORE_BASE64` (результат `base64 -w0 release.jks`), `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
  `KEY_PASSWORD` и выбирайте подпись **«Keystore из секретов GitHub»**.

Храните keystore и пароли в надёжном месте: без них обновить приложение в Google Play невозможно.

## Свой сервер сборки (Docker) — вместо GitHub

Образ публикуется workflow **Engine** в `ghcr.io/<владелец>/<репозиторий>:latest`.

```bash
docker run -d --name appbuilder -p 8080:8080 \
  -e ENGINE_TOKEN=придумайте-токен \
  -v appbuilder-data:/data \
  ghcr.io/<владелец>/<репозиторий>:latest
# или из исходников:
ENGINE_TOKEN=придумайте-токен docker compose -f engine/docker-compose.yml up -d --build
```

В приложении: «Настройки» → «Свой сервер» → `http://<IP компьютера>:8080` + токен.
Том `/data` хранит постоянный debug-ключ. Сервер выполняет код загружаемых проектов —
давайте доступ только тем, кому доверяете.

## Для разработчиков

```
packages/appbuilder_core/   анализатор ZIP, план сборки, контракт, генератор промптов, версии toolchain
engine/                     сборщик (Dart): CLI + HTTP API, шаблоны Android-проектов, Dockerfile, примеры
app/                        Flutter-приложение (Material 3, Provider)
docs/agent-contract.md      контракт для ИИ
.github/workflows/
  app.yml                   APK + Web + Linux + Windows, проверка на эмуляторах, релиз app-latest
  engine.yml                тесты, Docker-образ, сборка и запуск всех примеров на эмуляторах
  inbox-build.yml           сборка ZIP из inbox/ (режим «GitHub Actions» в приложении)
```

```bash
cd packages/appbuilder_core && dart test
cd engine && dart test
cd app && flutter test && flutter run
flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
```

Постоянный ключ подписи самого AppBuilder в CI: секреты `APP_KEYSTORE_BASE64`, `APP_KEYSTORE_PASSWORD`,
`APP_KEY_ALIAS`, `APP_KEY_PASSWORD` (без них используется ключ из кэша Actions).
